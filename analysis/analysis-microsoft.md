# Analysis: Microsoft's agent stack and "Frontier Firm" vision

Microsoft sells the parts around Cyclical's loop, not the loop. It ships agent identities in the same directory as employees (Entra Agent ID, each agent with a "named manager"), a business-wide context layer (Work IQ / Microsoft IQ), agents that put their work where people already work (Outlook, Teams, Business Central), model choice between OpenAI and Anthropic, and since late 2026 "agent refinements" that suggest turning repeated agent steps into workflows. It has nothing that grades agents or humans against real-world outcomes, no staged graduation, no process graph, and above all no cross-business pooling. Its core enterprise promise, that each customer's data stays inside that customer's account, rules out pooling. **Overlap: 4/10.** Microsoft owns the identity layer, the context layer and the drafts folder, but the part of Cyclical that compounds (outcome grading plus a pool across many businesses) is absent and conflicts with Microsoft's commercial model. The main lesson: Microsoft already sells "people and agents in one org chart, each agent with a manager" on 30M+ paid seats, so Cyclical should build on that layer and compete on the outcome loop Microsoft structurally can't run.

**Traction.** Paid M365 Copilot seats went 15M (Jan 2026) → 20M (Apr) → 30M+ (Jul 2026) [1][2]. Third-party estimates put that at ~6.6% of the ~450M paid commercial Office seats [2], so after almost three years on sale, about 93% of seats Microsoft could sell Copilot to still don't pay for it. The 2026 Work Trend Index reports active agents in the M365 ecosystem up ~15× year over year (~18× at large enterprises) [13] (vendor claim). Dynamics 365 revenue grew 13% year over year in Q4 FY26 [14]. Microsoft does not break out SMB Copilot seats, Copilot Studio agent counts or Business Central agent usage.

**The "Frontier Firm" framing** (2025 Work Trend Index; survey of 31,000 workers, 31 markets, by Edelman) [15]: three phases, from "AI as assistant" to "agents as digital colleagues" to "humans set direction and agents run entire business processes." Two coined terms. The **human-agent ratio** is "how many agents are needed for which roles and tasks, and how many humans are needed to guide them," called "task-specific" with no formula. The **agent boss** is the employee who "builds, delegates to, and manages agents." The report also proposes replacing the org chart with a "Work Chart" of goal-based teams. On measurement it says only to "onboard [agents], assign ownership responsibilities, and measure their performance," and defines no metric and no owner [15]. The 2026 edition (20,000 workers, 10 countries) moves to a "Transformation Paradox": only 19% of AI users sit in the "Frontier zone," and the organization, not the technology, is the bottleneck [13][16].

**Architecture, as it bears on Cyclical.** Everything sits on Microsoft Graph, a per-tenant graph of people, mail, calendar, files, chats and the manager hierarchy. A "tenant" is one customer's isolated Microsoft 365 account. Agents get Entra identities in the same directory as humans. Work IQ retrieves Graph context for any agent within the caller's permissions. Agent 365 registers and governs agents, including other vendors'. Copilot Studio's harness runs agents on OpenAI or Anthropic models. The newest pieces (Oct–Nov 2026) are **persistent agents** that belong to the organization rather than one person and are triggered by an email or a schedule, **business-process memory** shared across users ("a point one person raises becomes a shared resource for everyone else"), and **agent refinements**: planned recommendations, drawn from agent activity, to "convert repeated steps into workflows, capture reusable skills, resolve ambiguous instructions, or choose a better-suited model," which makers then "evaluate, test, and implement" [5].

### Aspects that matter most

**A3: Microsoft owns the drafts folder, and that cuts both ways.** Cyclical's stage-2 trick (agent drafts land in the person's drafts folder; sending = approval, editing = correction) runs entirely on Outlook in an M365 shop. Cyclical can do it through the Graph API today. That means Cyclical depends on Microsoft's API terms and admin consent. It also means Microsoft could add "track whether the draft was sent unchanged" in one release. Microsoft hasn't treated that signal as data: Copilot drafts are ephemeral suggestions, and Business Central's agents keep review inside the ERP's task pane, not in the inbox (from memory). The edit-diff stream is the part Cyclical should treat as proprietary. It sits on infrastructure Microsoft controls.

**A4: Microsoft is ahead on enforcement and on the "rules, not persuasion" principle.** Conditional access decides by who is asking, which resource and the risk signals, never by prompt text, which is exactly Cyclical's prompt-injection rule. Agents carry sponsors and lifecycle states, and Agent 365's network controls "block prompt-based attacks" and filter risky file movement [7]. What Microsoft lacks is Cyclical's inference step: repeated requests → propose a missing edge; unused grants → propose removal. Entra access reviews are periodic human attestations, not usage-driven proposals (from memory). **On Cyclical's unresolved question (who answers for data in a system node?), Microsoft's answer is the "sponsor" or "manager" pattern.** Every non-human identity (service principal, agent) has a human sponsor who owns its access. Cyclical called that inelegant, but it is the industry default, and SMB IT providers (MSPs) already administer it. Copying it costs nothing and is easy to sell.

**A8: "Agent refinements" is the closest Microsoft gets to Cyclical's ladder.** Recommendations to "convert repeated steps into workflows" are level 3 (compile to code); "capture reusable skills" is level 1; "choose a better-suited model" is model swapping [5]. The difference is the trigger. Microsoft proposes from activity patterns, and a human maker "evaluates and tests." Cyclical's rule is: compile when a simple rule reproduces the agent's outputs on N runs, then put the code through the same outcome-graded stages. Microsoft also fine-tunes (Copilot Tuning, from memory), the opposite of Cyclical's "retrieved examples survive model swaps" choice. For Microsoft that is consistent: it sells the model layer and can retune.

**A10: Work IQ is a shipped version of Cyclical's shared context layer, at tenant scale.** Any agent can draw on business-wide context (mail, files, meetings, CRM via connectors) within permission scope, and business-process memory is shared across users of a persistent agent [5]. Cyclical shouldn't try to out-build this for M365 customers. It should consume it.

**A11: Pooling is where Microsoft is structurally blocked, not just behind.** Microsoft's enterprise pitch rests on tenant isolation and on not training foundation models on customer data. Pooling one dental clinic's outcomes with another's (claim acceptance by insurer × procedure, recall-text show-up rates) would need a new consent model that Microsoft has little reason to build for a 9-person clinic. It is also horizontal. A dental clinic's outcomes (show-ups, claim payments) sit in Dentrix/Eaglesoft/Open Dental, not in Graph, and the clinic's appointment book lives in the practice software, not Outlook. The dental-clinic model found 12 of 14 typed handoffs end in the practice software, so Microsoft sees perhaps the email-and-phone slice of a clinic, not the graph.

## Where they're ahead of Cyclical

- **Distribution and installed base:** 30M+ paid Copilot seats, ≈450M commercial seats, and an MSP/partner channel that already administers SMB tenants. A Cyclical clinic on M365 Business Premium already has Entra, Outlook, Teams and Graph turned on.
- **Identity and governance for agents:** Entra Agent ID, agent "named manager," Agent 365 registry across Microsoft, AWS, Google, OpenAI, Anthropic and Salesforce agents, network-level prompt-attack blocking, cost controls with chargeback [6][7]. Cyclical's A4 is a design; Microsoft's is GA.
- **Context layer:** Work IQ / Microsoft IQ with 350+ connectors [10].
- **Runtime engineering:** persistent agents with triggers, shared memory, agent accounts with own credentials (preview Dec 2026), a hosted runtime for generated apps [4][5].
- **SMB accounting agents in a system of record:** Business Central's Payables and Sales Order agents work where SMB financial outcomes (invoice paid) are recorded [11]. For a BC customer, Microsoft owns both the action and the answer key, the position realizations.md §6 warns about.

## Where they're doing it differently (and whether their way is better)

- **Seat-centric vs process-centric.** Microsoft's unit is the *person* (the "agent boss" with agents under them; licenses per user). Cyclical's unit is the *process step*. Microsoft's way sells better (it flatters each employee and maps to per-seat billing) but can't answer "should this role exist?", because the role holder is the buyer. Cyclical's way is better for the clinic owner, who pays salaries, and worse for adoption among staff.
- **Autonomy by toggle vs autonomy by statistics.** Microsoft lets an admin switch off review. Cyclical graduates case types after n clean outcome-graded runs. Microsoft's way is simpler and fits SMBs that don't run experiments. Cyclical's is the only defensible one when the error costs money (claims, payments). Microsoft's published metric, "fully autonomous resolution rate" [4], rewards removing humans, a Goodhart target.
- **Evals as test sets vs evals as world outcomes.** Microsoft's evals are developer-time quality checks. Cyclical's are production-time outcome joins. Microsoft's are cheaper and generic; Cyclical's need the outcome data Microsoft doesn't hold for most verticals.
- **Fine-tuning vs retrieval for the per-business layer.** Microsoft offers tuning (from memory). Cyclical's argument (hundreds of examples, survive model swaps) is stronger at SMB volume.
- **Observation: aggregate and de-identified vs individual and graded.** Microsoft learned in Nov–Dec 2020 that per-person work scoring is toxic. "Productivity Score" drew a privacy backlash and Microsoft removed user-level names within weeks (from memory). Viva Insights now aggregates with minimum group sizes. Cyclical's shadow stage grades individual humans against outcomes. In a 9-person clinic, "the agent beat Maria on recall-call show-ups" is individually identifiable by construction. Microsoft's way is safer legally (GDPR, EU works councils) and for trust. Cyclical needs an answer before its first European or unionized customer, and a framing for US staff ("we grade the step, not you").

## Top-level: why they chose this path, and what to learn

**Starting asset and constraints.** Microsoft starts with the identity directory and the communications record of most of the world's offices, sold per seat to IT departments. That explains every choice. (1) Per-seat billing makes the employee-as-"agent boss" the hero; a product that proposes removing the front-desk role would cannibalize seats and alarm the IT buyer's own users. (2) Selling to IT makes governance (Entra, Agent 365, Defender) the lead product, because IT buys control before it buys outcomes. (3) Tenant isolation is the trust contract that lets Microsoft hold everyone's email; pooling outcomes across tenants would break it. (4) Being horizontal at 450M seats means Microsoft never sees a dental clinic's answer key (insurer remittances, show-ups), which lives in vertical software. (5) The 2020 Productivity Score backlash taught it not to grade individuals.

**What this implies for Cyclical.**
- *Copy:* the identity model. Every Cyclical agent should be an Entra (or Google) identity with a named human sponsor, registered in Agent 365 if the customer has it, governed by conditional-access-style rules. It answers the system-node question pragmatically and passes the MSP's security review. Also copy the "refinements" UX: proposals a manager accepts, not silent changes.
- *Build on, don't rebuild:* Outlook drafts via Graph for stage 2, Work IQ/Graph for shared context, the Microsoft model router for model-agnosticism where the customer is on M365. Cyclical can be a Copilot/Agent 365 partner agent.
- *Avoid:* "autonomous resolution rate" as the headline metric; manual autonomy toggles; individual-level worker scoring without a privacy design; per-seat pricing that pays more for more humans.
- *Exploit:* the three things Microsoft can't do by design. Join agent actions to vertical outcome data in the practice software and payer remittances. Pool those outcomes across clinics under an explicit DSO-style data agreement. Run randomized role-removal experiments that a seat-licensing vendor won't run.

**Relationship.** Cyclical is **orthogonal-to-superset**: it uses Microsoft's layers (identity, context, inbox) as substrate and adds the outcome-graded, pooled loop on top. It isn't a clone. Microsoft's product points at the individual knowledge worker, Cyclical's at the business process.

**Threat level: moderate for SMBs on M365, low for dental specifically over 2–3 years** (rough probability Microsoft ships outcome-graded, cross-tenant pooled agent improvement for a vertical SMB segment by end-2028: ~10–15%). The bigger near-term risk is that Microsoft makes the *substrate* good enough that a dental practice-software vendor (the system-of-record owner realizations.md §6 worries about) builds Cyclical's loop on Copilot Studio + Agent 365.

**Signals that the threat is rising:**
1. Agent 365 Business Analytics adds connectors that join agent actions to external *outcome* records (payments, appointments) and reports per-process outcome rates, not just "work completed."
2. Microsoft introduces opt-in cross-tenant *outcome* benchmarks for agents (it already does anonymized adoption benchmarks, from memory).
3. A Copilot "industry skills" plugin for healthcare front office or dental, or Dragon Copilot (Microsoft's clinical documentation product, ex-Nuance) extended to dental.
4. A dental practice-software vendor (Henry Schein One, Planet DDS, Patterson) announces agents built on Copilot Studio/Agent 365.
5. Outlook starts logging "draft sent unedited / edited / discarded" as an agent-feedback signal exposed to makers.
6. Business Central agents start graduating autonomy automatically based on measured error rates rather than admin toggles.
